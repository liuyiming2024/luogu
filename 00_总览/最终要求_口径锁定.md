## 由澄清带出的全局约束

- **离线优先**：本地 HTML 浏览与发文；发文先本地保存；只有「已登录洛谷账号 + 联网」才回推 `luogu.com.cn`
- **评论推洛谷**：本地先存 → 待推队列 → 由「能出网且持有登录态」的一端低频推洛谷；
  静态 Pages **绝不直接 fetch 洛谷**（跨源 + HttpOnly cookie + CSRF 不可达），详见《架构可达性测试报告》
- **本库即数据源**：文章 / 讨论区 / 题面 / 工单四类内容自行维护；联网用户浏览时抓取所浏览内容、**延迟维护**，源已删则本地也删
- **std 准入**：对拍 → 去 WA 与不优 → 可选工单 → 人工审核无错 → 迁入 std
- **只认 token 不认人**：所有管理/API 能力以 token 为准，不校验自然人身份
- **账号使用**：两个低频检索账号仅用于「审 std / 删资源」；本人持有的低频检索账号（凭据仅存 Secrets / 本机） 仅在这类**低频、无风险、必需**的请求里使用
- **真编译**：借洛谷 IDE、用用户个人账号、联网已登录（第 10 条），静态站不碰登录态
- **后果自担**：确认门是明示同意与责任划分，不是安全边界；真鉴权仍靠 token（第 11 条）
- **不落凭据**：账号、密码、cookie、token 一律不写进公开仓库；只走环境变量 / Actions secrets / 浏览器本地缓存
- **单人自用**：不设角色体系；所有能力以「本人 + token」表述，公开页面与文档不出现角色字样
- **运行态自加**：静态 Pages 不承担运行态；Actions runner / 本机脚本由使用者自行添加或下载
- **自担后果**：本人首次一次性授权（Secret），之后自动提交；前端每笔仍过「我自担」确认门。未授权则预览态不向洛谷发任何写请求
