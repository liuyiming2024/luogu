# 归档与版权声明

> 本仓库已按归档者意见设为**公开**，并上线 GitHub Pages 归档库网页。
> 本文说明收录边界、署名规则、完整性签名与移除入口。

## 1. 收录边界

本仓库为**个人学习 / 学术研究**目的，对洛谷（www.luogu.com）上**公开可访问**的
题面、题解文章与少量规范/学术类文章做离线归档与校对留痕：

- 只收录**无需登录即可公开访问**的页面内容
- 不收录用户私有数据、不收录账号凭据、不收录需授权才能看到的后台内容
- 不做商业用途、不用于再分发牟利、不宣称对第三方内容拥有权利
- 「校对」指完整性、代码块可提取性、题面合规性与三类缺陷对拍，**不是**对原文 correctness 的背书

洛谷全站题解约 16 万篇；本库是**已发现并登记的全部编号**，并非全站镜像。
新增条目由低频取回逐篇补录，进度见 `02_文章编号索引/爬取进度.md`。

## 2. 每条都带原文引用与「签名」

「引用原文、要有签名」在本库落地为四项可核对字段，由
`tools/provenance.py` 生成 `site/data/provenance.json`，
并渲染进每篇文章页的「引用与署名」块：

| 字段 | 含义 |
|---|---|
| `original_url` | **原文链接**，指向 `www.luogu.com/article/<8位编号>` 或题面页，页面可点击 |
| `author` | **作者署名**：从页面 meta 尽力提取；抓不到就写「见原文页面署名」，**不编造** |
| `fetched_at` | 取回时间，说明内容对应哪个时点的原文 |
| `content_sha256` + `signature` | **内容完整性签名**：sha256 绑定「编号 / 原文 URL / 内容哈希 / 取回时间」，供离线核对正文是否被改动 |

`signature` 是**内容完整性校验值**（sha256 派生），不是加密学意义上的数字签名，
也不代表原作者授权；它只回答「归档副本与取回时是否一致」。

页面底部提供一段**可直接复制的引用格式**：

```
作者. 《标题》. 洛谷, 原文: https://www.luogu.com/article/xxxxxxx
（本仓库归档于 时间，内容 sha256: 前16位，完整性签名: 前32位）.
版权归原作者所有，仅作学术归档引用。
```

无正文的条目也生成「仅索引签名」，明确标注「正文待补录」，不假装已引用全文。

## 3. 权利归属

- **题解、题面、专栏正文的版权归原作者及洛谷所有**；本仓库不对其授予任何许可，
  也不以开源许可证覆盖第三方内容
- 仓库自身的脚本、生成器、报告与归档结构仅为整理者的工作产物
- 站内保留原文链接与作者署名；离线副本仅作引用与校对留痕
- 若权利人、原作者或平台不希望某条内容被收录，**可提交 issue 或联系仓库维护者**，
  我们会删除对应正文、`ingested/` 副本、索引条目与页面，并在日志里登记移除

## 4. 三角架构（谁在哪跑）

| 环节 | 位置 | 说明 |
|---|---|---|
| **爬取** | GitHub Actions（那边） | `crawl_tick.yml` 每天 4 次错峰 tick，随机起步、2~3.5s 抖动、降级即停；结果 commit 回仓库 |
| **对拍 / 三类判定** | 本地（这边） | `tools/verify_pipeline.py` 消费待对拍队列，需独立正确解，不放在 Actions 自动下结论 |
| **网页归档库** | GitHub Pages（那边） | `pages.yml` 把 `site/` 发布成公开静态站，每条带 §2 的引用与签名 |

对拍结果由本地 push 回仓库后，Pages 自动重生成，网页始终与仓库一致。

## 5. 隐私与安全

- 仓库内**无账号、无密码、无令牌**；token 仅经环境变量 / Actions secrets 传递
- 改公开前已扫描工作树与**全部 git 历史**，确认无凭据残留
- 站内静态页无 CDN、无第三方脚本、无统计像素、不发起网络请求（原文链接为用户主动点击才跳转）
