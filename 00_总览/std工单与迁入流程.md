# std 工单（投稿）与迁入流程

> 背景：**取不到官方数据**，所以正确性以 **std 对拍**为准，
> 而不是假装手里有官方测试数据。

## 状态机

```
投稿（工单）
   ↓ 与原 std 对跑比较
   ├─ WA              → 去除（不进入候选）
   ├─ 结果正确但不优  → 去除（时间/空间明显劣于原 std）
   └─ 不 WA 且更优    → 添入「可选项」
                            ↓ 人工审核（本人：审 std）
                            ├─ 有错 → 打回 / 去除
                            └─ 无错 → 迁入 std
```

## 判据

| 项 | 口径 |
|---|---|
| 官方数据 | **无**。不编造、不引用不存在的官方 std/测试点 |
| 对拍 | 自写独立正确解 + 题面内输入；与原 std 多轮对跑 |
| 去除 WA | 任何题面内确定性 WA/RE 直接淘汰（沿用甲类口径） |
| 去除不优 | 与第 1 批起的三类口径一致：**最小时间/空间、省资源**是默认要求；明显劣于原 std 不收 |
| 不优的定义 | 同输入下输出一致但耗时/内存明显更差，或依赖更大数组/更慢算法 |
| 人工审核 | 本人（见《本人操作与 token 约定》）逐条确认后迁入，脚本不自动迁入 |

## 与现有对拍体系的关系

- `03_验证脚本/` 与 `05_对拍原始数据/` 已提供独立正确解 + 变异版敏感性检查
- `tools/verify_infra.py` 的「变异必须被抓到」纪律同样适用于 std 投稿：
  **对跑比较若抓不到已知反例，判为空跑，投稿不通过**
- 第 17 批 `yk90rg78` 翻案说明：**转录位置也是语义**，投稿代码必须回原文/原文件逐字核对

## 前端入口

结果由本人在 `admin.html` 审核。接口契约见 `api/API契约.md`。
