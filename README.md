## 「枚举」的确切含义

`02_文章编号索引/判定口径.md` 与 `06_离线复现说明.md`。

## 差值推送 · 推送前体检（第 18 条）

仓库只有 **4.3 MB / 586 文件**，慢的不是体积，是「每轮都全量重跑、每次 push 都触发两个工作流、推送后还等部署」。已改：

| 项 | 处理 |
|---|---|
| 拉取 | 所有工作流 `fetch-depth: 1` 浅克隆 |
| 触发 | Pages 只在 `site/**` / 生成器 / 工作流变化时跑；代提交只在 outbox 变化时跑 |
| 提交 | `git diff --cached --quiet` 无变化直接跳过；生成器幂等，未变产物不进提交 |
| 题面取回 | 内容没变不写文件、不计新增（run 3 实证 `diag-ok0-fail0` 零提交） |
| **等待** | **推送后一律不等 Pages**；改由 `tools/precheck_pages.py` 在**下一次推送前**查上一次 Pages 结论 + 跑本地自检（坏链/敏感/角色/闸门/朴素对拍），异常只 `::warning::` + 留痕，不阻塞 |

另外 `fetch_problem.py` 加了 `--auto-range`：按 `crawl_state.problems_cursor` **有序推进**，
跳过已有正文级存档的 P 号，每轮一批，成功才推进游标；不再靠手写 P 号列表。

补充两点（本轮实测）：

- **台账内容幂等**：`tools/std/stable_write.py` 剥离时间类元数据后比对，
  内容没变就不写盘；连跑两次 `verify_brute` + 全链路，git 变更数不再增长。
  这解决了「内容一样只有时间戳变了」的无用 diff。
- **题面会领先 STD**：`--auto-range` 已自动爬到 `P1003`（远端第 8 份题面）。
  检查口径改为 **STD ⊆ 题面**，并显式列出「题面待补 STD：P1003」——
  不凭空写 std、不假装 8 题都做了朴素对拍。补 STD 是逐题的长期工作。

**本轮抓到并修掉一个真 bug**：run 6 的诊断是 `diag-ok10-fail0-h200x50-r6`
（真取回了 10 题正文），但提交链里没有它、游标还停在 P1022 ——
原因是工作流把**可能不存在的**「上一次部署体检.md」和题面文件塞进同一条

### 本轮抓到并修掉的 5 个真问题（都是「保证做的是对的」的实证）

1. **P1034 std 不精确**：原「x/y 双向区间 DP」对 k≥3 的**混合方向划分**会漏解，
   全量 40 组里 `n=6,k=3` 给 118 而精确解 114、`n=7,k=4` 给 69 而精确解 26。
   已升级为**递归枚举双向切分 + 记忆化**的精确解，并把全量 40 组固定为回归检查点。
2. **P1038 std 输入层判定失效**：`indeg` 同时用于拓扑递减与「是否输入层」判断，
   处理节点时入度已归零 → 样例输出 `NULL`。改为保存 `orig_indeg`。
3. **P1040 朴素枚举漏题面特判**：题面逐字「叶子的加分就是叶节点本身的分数，
   不考虑它的空子树」，朴素套 `f*f+d` 把叶子算成 `d+1` → 冒出 211（正解 145）。
4. **P1041 bitmask 位偏移**：节点编号从 1 起，初始状态应为 `1<<1` 而非 `1`，
   朴素给出 1（正解 3）。
5. **P1037 生成器 `k=0` 多写空行**：被 `in_range` 正确拦下；同时修正校验里
   `len(L)<2` 的硬门槛（无规则也是合法输入）。
