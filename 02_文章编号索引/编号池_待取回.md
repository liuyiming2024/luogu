# 编号池 · 待取回队列说明

本文件**不是**全站编号清单，而是「已发现、待逐字取回」的有序队列说明。

- 权威主表：`article_index.csv`（按题号升序 → 编号字典序）
- 取回器：`site/lowfreq_fetch.py`，默认 2 秒/次，只消费主表里
  `是否题解=是` 且 `可逐字验证 != 是` 的条目
- 取回结果：`site/data/ingested/<lid>.json` + `取回日志.jsonl`
- 生成器 `_build_site.py` 会自动合并 ingested 正文到文章页
- **重生成不会删除** `site/ingest.py`、`site/lowfreq_fetch.py`、
  `site/data/ingested/`；这几个是常驻资产，模板在 `02_文章编号索引/`

新增编号流程（有序、低频、不遍历）：
1. 拿到一个明确的 8 位编号（来自你给的链接、搜索结果、或保存站文章广场）
2. 用 `python3 site/ingest.py new.json` 追加进主表（标「待补录」）
3. 用 `python3 site/lowfreq_fetch.py --lids <lid> --delay 2.0` 取回正文
4. 人工判定「是否题解」→ 更新主表 → `python3 _build_site.py` 重生成

> 为什么没有「全站 16 万篇编号列表」：保存站的文章广场 / 搜索 / 统计页都是 SPA 骨架，
> 静态取回只返回导航文字；正文与列表靠 JS 调保存 API，而保存站首页挂着
> 「AI 自动化程序不断请求保存 API，导致队列堵塞」的降级公告。
> 当前沙盒出口对 luogu.me 全路径返回 403 policy_default_denied。
> 详见 `保存站可用性记录.md`。
