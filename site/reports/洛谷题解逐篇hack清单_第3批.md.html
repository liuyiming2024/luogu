2.1 P5638 nzmytiez · 已 hack（k ≥ n 时滑动窗口一次不跑）

文章把代码拆成 5 段给出（核心代码 / 头文件初始化 / 读入 / 输出 / return），按文章顺序拼成完整程序；逐字保留后的最终版核心：

int n, k, a, b;
long long cxk[1000010], ans, maxx, ans2;
cin >> n >> k;
for (int i = 1; i <= n - 1; i++) cin >> cxk[i], ans += cxk[i];
a = 0, b = a + k;
for (int i = a; i < b; i++) ans2 += cxk[i];
for (int i = 1; i <= n - k; i++) {
    ans2 = ans2 + cxk[b] - cxk[a];
    maxx = max(maxx, ans2);
    a++, b++;
}
cout << ans - maxx;

题面：n ≥ 2, k ≥ 1, ai > 0；测试点 1~10 n,k ≤ 100, ai ≤ 10^5，测试点 24~25 n,k ≤ 10^6, ai ≤ 10^12。传送器「目标城市编号大于 n 则为 n」——k ≥ n 完全合法，此时从城市 1 一次传送直接到城市 n，节省全部道路，答案应为 0。

被卡原因：for (int i = 1; i <= n - k; i++) 在 k ≥ n 时上界 n-k ≤ 0，循环一次都不进，maxx 保持初值 0，于是输出 ans（总长度）。题解只枚举了「恰好 k 条连续边」的窗口，没有处理传送目标被 clamp 到 n 的情形。

反例（题面内、确定性 WA）

输入期望实际
2 100 / 505
3 5 / 2 305
4 4 / 7 1 9017

对照组（证明是边界而非逻辑错）：官方样例 1 4 0 / 1 2 3 → 6 ✓；样例 2 4 1 / 1 2 3 → 3 ✓；k=n-1 的 4 3 / 7 1 9 → 0 ✓；5 2 / 10 10 1 1 → 2 ✓。

200 组随机小数据（n=2~25, k=1~35）中 133 组不一致，全部是 k ≥ n 情形；k < n 的组 0 处不一致。

两点说明： 1. 文章前面还给过一份「朴素两层循环」实现并自己指出「毒瘤数据范围」后给出滑动窗口作为核心代码，命中针对的是这份最终优化版。 2. 另一篇 P5638 题解记录了「i 从 1 开始循环会漏掉第 0 个位置、实测 92 分、测试点 6/10 WA」，属于同类边界问题在洛谷真实数据里的旁证；本批不引用它作为反例来源，反例全部本地独立构造。

2.2 P1803 dmza5ifn · 未 hack

逐字代码要点（原页 main(){ 为老式 C 写法，C++17 下补 int 返回类型，其余逐字）：

int cmp1(const void *a,const void *b){ return ((int*)a)[0]-((int*)b)[0]; } // 按开始
int cmp2(const void *a,const void *b){ return ((int*)a)[1]-((int*)b)[1]; } // 按结束
qsort(time,n,sizeof(int)*2,cmp1);
qsort(time,n,sizeof(int)*2,cmp2);
for(i = 1; i < n; i++){
    flag = 1;
    if((time[i][0]>=time[pos][0]&&time[i][1]<=time[pos][1]) ||
       (time[i][1]>time[pos][0]&&time[i][1]<=time[pos][1]) ||
       (time[i][0]>=time[pos][0]&&time[i][0]<time[pos][1]) ||
       (time[pos][0]>time[i][0]&&time[pos][1]<time[i][1])) flag = 0;
    if(flag == 1){ pos = i; count++; }
}
printf("%d", count);

题解文字说「按时间差从小到大」，但代码最终用 cmp2 按结束时间排序（第一次 cmp1 只影响相同结束时间的相对顺序），实际是标准区间调度贪心；四个 OR 条件在「按结束时间升序、e_i ≥ e_p」的前提下覆盖了全部重叠情形，s_i >= e_p 的完美衔接不会被误判。

验证：官方样例 3 / 0 2 / 2 4 / 1 3 → 2 ✓；短区间错觉反例 0 5 / 5 10 / 4 6 → 2 ✓；早开始长区间反例 → 4 ✓；单点衔接链 → 5 ✓；400 组随机（n=1~12，用枚举所有子集求最大兼容区间数作独立正确解）0 处不一致。

结论：未 hack。（文字描述与代码不一致属于表述问题，按本口径不计。）

2.3 P1018 pmio8se0 · 已 hack（DFS 剪枝少算一个乘号间隔）

题解用 DFS + 高精度乘法，关键剪枝与入口（逐字）：

void dfs(int xx,string u,int v,string ans){
 if(n-xx-1<v) return;                     // ← 剪枝
 if(v==0){ string uu=""; for(int i=xx-1;i<n;i++) uu+=x[i];
           ans=add(ans,uu);
           if(ans.size()>ma.size()||ans.size()==ma.size()&&ans>ma) ma=ans;
           return; }
 u+=x[xx-1];
 if(v>0) dfs(xx+1,"",v-1,add(ans,u));
 dfs(xx+1,u,v,ans);
}
int main(){ cin>>n>>k>>x; dfs(1,"",k,"1"); cout<<ma; return 0; }

题面：6 ≤ N ≤ 40, 1 ≤ K ≤ 6，样例 4 2 / 1231 → 62（用来校验独立正确解，结果一致）。

被卡原因：xx 是当前字符的 1-based 序号，从 x[xx-1] 之后到串尾共有 n-xx 个可放乘号的间隔，剪枝写成 n-xx-1 < v，少算最后一个间隔 → 永远无法在最后两位之间放乘号，所有「最后一段仅 1 位」的分法被漏掉；当 k = n-1 时入口处 n-1-1 < n-1 直接 return，ma 保持空串，输出空。

反例（题面内、确定性 WA）

输入期望实际说明
6 1 / 1234567407069104最优 12345×6，题解最好只能 1234×56
6 4 / 12345643201344同上
6 5 / 123456720（空串）k=n-1，入口即被剪掉
7 6 / 10203040（空串）k=n-1，含 0
9 6 / 5655089352790000018900000常规规模也挂

独立正确解：区间 DP dp[i][j] = max_{p<i} dp[p][j-1] × int(s[p:i])（Python 大整数），官方样例回算 62 ✓。300 组严格合规随机（N=6~40, K=1~min(6,N-1)）中 63 组不一致，K 越大命中越密集（K=6 时 24/… 组挂），与剪枝缺陷吻合。

顺带核对过题解的高精度乘法 add()：q[10005]/p[1005]/qp[1005] 在 N≤40 时够用，进位与去前导零正确；WA 的根因就是剪枝，不是精度。

2.4 P1090 zcxe384l · 未 hack（附两处不计项）

手打小根堆的哈夫曼解。逐字版 pop() 写成

void pop() { heap[1]=heap(heap.size()-1); heap.pop_back(); gao(1); }

heap(…) 是对 vector<int> 对象的函数调用，C++ 下 CE（no match for call to '(std::vector<int>) (…)'）。这属于与输入无关的展示缺陷，按本口径（要求存在测试点）不计为 hack；把 [] 补回成 heap[heap.size()-1] 后：

  • 200 组随机（n=1~40, ai≤20000）与 heapq 哈夫曼独立解 0 处不一致；
  • 下沉 gao / 上浮 doit / 哨兵 -1e9 逻辑均正确。

明确作废的一条：我构造过 n=10000 全 20000 想卡 int ans，其真实答案 2672320000 > 2^31-1，补正版输出 -1622647296（确实溢出）。但 P1090 题面写明「输入数据保证这个值小于 2^31」，该输入违反题面保证，因此不算合法反例，作废。

结论：未 hack。
