架构可达性测试报告

目的：在继续实现前，先回答「是否有难以实现的架构」。 方法：只读探测（不登录、不提交凭据、间隔 2 秒）+ 静态资产自检 + 浏览器模型推断。 可复跑：python3 tools/check_reachability.py（默认不发任何网络请求； --probe 才做只读状态码探测，且不带任何账号信息）。

〇、为什么「静态 Pages 直连洛谷写操作」不可达（原理详解）

先给结论：不是洛谷不能写，也不是网络不通，而是「第三方域下的网页 JS 不能以用户身份向另一个域发起带登录态的写请求」被浏览器模型禁止。 三层锁叠着，缺一层都还有办法绕，三层一起就死了。

锁 1 · 同源策略 / CORS：响应根本到不了 JS

页面在 https://liuyiming2024.github.io/luogu/，请求发往 https://www.luogu.com/...，协议+域名+端口不同 = 跨源。

写操作（POST + JSON + 自定义 header）不是「简单请求」，浏览器会先发 OPTIONS 预检，问洛谷：「允许我这个源吗？」洛谷不返回 Access-Control-Allow-Origin: https://liuyiming2024.github.io， 浏览器就直接把后续 POST 和响应一起丢掉。

关键：JS 连「失败原因」都拿不到，只会看到一个笼统的 TypeError。 所以这不是「返回 403」，是请求压根没被允许发出 / 响应压根没交到 JS 手里。 （顺带区分：实测沙盒 curl 全 403 是*出口策略网关*默认拒绝，发生在更外层； 即使换成能出网的机器，锁 1 依然存在。）

锁 2 · HttpOnly + SameSite cookie：钥匙你摸不着

洛谷的登录态是一枚会话 cookie。就算对方愿意放行 CORS：

  • HttpOnly：JS 的 document.cookie 读不到它，没法手动塞进

Authorization 或自定义 header；只能靠浏览器自动带。

  • credentials: 'include' 能让浏览器自动带，但写请求还要洛谷返回

Access-Control-Allow-Credentials: true 且 Access-Control-Allow-Origin 不能是 *（必须是精确源），第三方站拿不到。

  • SameSite=Lax/Strict：在跨站子请求里，浏览器根本不会带上这枚 cookie。

所以「用用户的账号」这句话，在第三方域的 JS 里物理上做不到—— 钥匙在浏览器手里，但保安（同源策略）不让它交给外人。

锁 3 · CSRF token：就算混进去也验不过

洛谷页面里的 csrf-token 是服务端按当前会话渲染的，写在 HTML meta 里， 每次会话/有时每次请求都变。第三方静态页：

  • 读不到洛谷页面里的 token（跨源读 HTML 同样被拦）；
  • 就算拿到了，也无法保证和浏览器里那枚会话 cookie 对应；
  • 写接口校验不通过 → 403/401。

为什么 curl / 后端 / 扩展 / 洛谷自己的页面却可以

执行端为什么不受这三锁
curl / Python 后端不是浏览器，没有同源策略；cookie 由你手动管，token 自己取
浏览器扩展（host permissions）扩展有声明过的跨域权限，可带 cookie
洛谷域下自己开的页面（IDE / 文章页 / 提交页）同源！cookie 自动带、token 就在本页 DOM 里
本机代理 / 自托管 runner等价于后端，且持有用户个人的登录态

一句话类比：你站在别人家门外（github.io），想用人家屋里的钥匙 （HttpOnly cookie）替人家开门办事；浏览器这个保安不允许钥匙出门。 但你自己走进屋里（打开 luogu.com 的 IDE/文章页）就随便用—— 这正是第 10 条「借洛谷 IDE」和第 9 条「评论推洛谷」能成立的原因。

精确措辞

「架构级不可达」= 第三方域静态 JS 无法以用户身份对洛谷发起写请求。 不等于「洛谷不可写」「评论推不了」「真编译做不了」。 换执行端（洛谷域页面 / 本机代理 / 扩展）后全部可达。

关于「全 403」的重要区分

这不是站点挂了，也不是频率被限，是沙盒出口策略网关的默认拒绝（响应体 No policy rule matched the request / policy_default_denied）。同一时段：

  • GitHub Actions 出口取洛谷文章正文为 HTTP 200（azdjstpm 8836 字节，第 15 批实证）
  • 另一读取通道读 liuyiming2024.github.io/luogu/ 返回正常 HTML（87 篇）

所以结论是「当前这一端出不去」，不是「目标不可达」。架构因此必须把 取回放 Actions、推送放能出网且持有登录态的一端，而不是全塞进静态站。

二、三个真正的难点

难点 1 · 静态 Pages 浏览器直推洛谷 —— 架构级不可达（硬障碍）

与新口径「评论持久化直接推洛谷」直接相关。与 403 无关，是浏览器模型决定：

障碍说明
跨源Pages 域 liuyiming2024.github.io ≠ www.luogu.com，写操作触发 CORS preflight
响应头洛谷不返回 Access-Control-Allow-Origin: *，浏览器阻断响应
凭据登录态是 HttpOnly + SameSite cookie，跨站 credentials: 'include' 带不过去
CSRF页面 csrf-token 与会话绑定，静态页拿不到也用不了

curl / 后端不受这四条限制，浏览器一定受。 所以「直接推洛谷」不能用 fetch("https://www.luogu.com/...") 实现。

落地形态（已实现）：

文章页写评论
   ↓ 本地先存（localStorage，离线可看）→ state: 本地已存
   ↓ 待推队列（显式开关 + 配置了 apiBase 才启用）
   ↓ POST /api/comments/push-luogu   ← 交给「本机代理 / 自托管 runner / 浏览器扩展」
   ↓ 该端持有用户个人账号登录态，低频、人工确认、可一键关闭
   ↓ 洛谷文章评论区（权威持久层）
   ↓ 回写 state: 已推洛谷 / 失败待重试
  • 洛谷 = 权威持久层；本地 = 离线镜像 + 队列，不另建评论数据库
  • 用用户个人账号；管理员账号（liuyiming2024_1 / liiyiming2024_1）不参与评论
  • 静态站代码里没有任何直接指向 luogu.com 的写请求
  • 与「发文回推 luogu.com.cn」复用同一个适配器（/api/publish）

难点 2 · 浏览器内真编译 —— 已按第 10 条降级为「可达」

原判断：静态站自身无 WASM / g++ / CPython，浏览器内真编译能力级不可达。 用户给出更优解：可以要求对方联网且已登录，用对方自己的账号 借洛谷 IDE 真编译。这把问题从「自己造编译器」变成「换执行端」， 与难点 1 的规避同构，而且更省事——不用自建 runner、不用打包 emscripten。

落地形态（已实现）：

IDE 页写代码
   ↓ 点「洛谷 IDE 真编译」/「提交洛谷评测」（先过第 11 条确认门）
   ↓ 新窗口打开洛谷域下的 IDE / 题目页（同源！登录态自动生效）
   ↓ 代码经剪贴板粘贴 → 由洛谷自己的 IDE 编译 / 评测
   ↓ 静态站：不 fetch 洛谷、不读 cookie、不碰内部 API
  • 入口 URL 可在「设置」里按你所在网络自行确认（默认

https://www.luogu.com/ide、提交页模板 .../problem/{pid}）； 不编造洛谷内部 API，因为当前沙盒出口 403 无法实测真实路径

  • 局限如实说：新窗口打开 + 剪贴板是「人手动粘贴」，不是程序化一键提交；

若以后要全自动，仍需扩展 / 本机代理持有登录态，那是另一个执行端

  • 离线兜底保留：库中 site/data/judge_cases.json 的 std 期望输出对照，

断网也能用（浏览器本身依然不编译）

难点 3 · 写操作风控 —— 可达但高风险

评论 / 发文 / 回推都是写操作，比 GET 更容易触发风控与封号。 沿用「别给我封了」：2.0~3.5s 抖动、每 20 次小憩、50 分钟窗口 / 15 分钟静默、 403/降级长退避 30 分钟、失败不轰炸重试、默认关闭、仅个人账号。

四、结论

有难以实现的架构，且只有一处是硬的：静态 Pages 不能自己直连洛谷做写操作 （CORS + HttpOnly/SameSite cookie + CSRF 三锁，见「〇」）。 规避方案明确、已落地为「本地队列 + 外部执行端」适配器，不需要改目标—— 评论依然直接推洛谷、依然是权威持久层，只是发请求的不是浏览器。

按第 10 条，真编译已降级为可达：借洛谷 IDE、用用户个人账号、联网已登录， 新窗口 + 剪贴板，静态站不碰登录态。

按第 11 条，风险归属已交给用户自己：所有写操作 / 借账号动作前弹确认门， 列明账号与平台痕迹，勾选 + 输入「我自担」才执行，本地留审计。 写操作风控仍保留低频、默认关闭、失败不轰炸作为默认保护，但责任由确认人承担。
