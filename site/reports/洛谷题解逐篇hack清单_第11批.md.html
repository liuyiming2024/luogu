3. 丙类逐篇（关键验证点）

P1067 hu58r34f：if(x>0&&i!=n) 用 i==n 判首项——靠题面 aₙ≠0 成立；abs(x)!=1||i==0 保证常数项 ±1 输出数字、高次项 ±1 省略 1。两个官方样例 100x^5-x^4+x^3-3x^2+10、-50x^3+1，以及全 ±1 链 x^4-x^3+x^2-x+1 全部一致。2022.8.1 新增 hack 数据（n=100、首项 ±1、其余全 0）实测输出 x^100，正确。

P1100 qle49r7h：把数转 32 位二进制字符串 → 交换前后 16 位 → 转回十进制。独立解用 ((n&0xffff)<<16)|(n>>16)。0、1、65535、2³²−1、2147483648 等 10 定点 + 300 组随机全对；zhuan 里 for(int i=1; a.size()<32; i++) a='0'+a; 看似只补一次，实测每次循环长度 +1 直到 32。

P1308 03xk59dp：cin>>ci → getchar() 吃换行 → getline 读文章 → s+=' ' 保证末词结算；cur=i-ci.size() 给出 0-based 首字母位置。行首空格、连续空格、大小写混合、单词作为子串（abc abcd abc 不计 abcd）全部一致。

P1150 aceg4kbr：解法一 do{count+=n; end+=n; n=end/k; end%=k;}while(n>0)；解法二 n+(n-1)/(k-1)。边界 100000000 2 → 199999999（int 未溢出），两块各 300 组随机一致。

P1042 m16r8nbd：while(cin>>S) 逐字符读到 E（自动跳过换行），11 分制与 21 分制之间 有 puts("") 空行。评论区有人提醒「中间需要加空行」，实测代码已写。额外跑了题面管理员附注的黑数据规模：2501 行 × 25 = 62525 字符，char s[250000] 不越界、输出与独立解逐行一致。

P1706 两篇：jm3biw0r 用 next_permutation(a+1,a+n+1)（int a[10]={0..9}，n≤9 时 a+n+1 正好是尾后指针）；wiofo14v 用 DFS 回溯 + setw(5)。n=1..6 与 n=9 的输出与 itertools.permutations 逐字节比对全量一致（含 n=9 的 362880 行）。

P1739 z3dolqp8：count++/-- + if(count<0) break + count==0?"YES":"NO"。两个官方样例、))((、(()、裸 @ 等 9 定点 + 300 组 0 不一致。

P3397 smtoxvvs：二维差分四行加减 + map[i][j]=map[i][j-1]+map[i-1][j]-map[i-1][j-1]+d[i][j] 恢复前缀和。官方样例、n=1000/m=1001 满规模（含贴右下角的矩形触发 d[1001]）全部与独立二维差分一致。

P1116 vt4bqm6v：归并排序求逆序对，ans += mid-i+1（long long）。7 定点 + 200 组随机排列与 O(n²) 暴力计数一致。

P2089 vgwp3k30：10 层 1..3 枚举、zl[ans][0..9] 存方案、按字典序输出。n=20 方案数 8953，n∉[10,30] 输出 0，10 个定点全量逐字节一致。

4. 本批 6 次「差点误判」自查（重点）

#我一度以为实测结论处理
①P3397 map 名字歧义 → 编译失败，甲类error: reference to 'map' is ambiguous 是我自己补的 using namespace std; 造成的。回原文逐字核对：#include<bits/stdc++.h> 之后直接就是 #define N 1010，原文无 using 行。编译对照：带 using → rc=1；不带 using（原文）→ rc=0。原文依靠 bits/stdc++.h 把 printf/scanf 放在全局，裸 map 只解析到全局数组，无歧义不是 hack；补最小外壳补错了，已改回原文并重验
②P2089 有 4 个定点 full_match:false（n=9/31/5000/1）是我的独立解在无方案时漏了末尾换行：题解 cout<<ans<<endl 输出 0\n，我写成 0。修正独立解后 10 个定点全 true不是 hack；延续第 5/9 批「假命中先回查自己」
③P1067 全 0 系数 / 首项系数为 0 时输出空串或 +5 → 缺陷题面 aₙ≠0 明确排除；2 / 0 0 5（题面外）输出 +5、0 / 0 与 3 / 0 0 0 0 输出空串，全部登记为不合规输入。查 2022.8.1 新增 hack，实为 n=100 且首项 ±1（考 x^100 的指数输出），题解输出 x^100 正确不是 hack，归丙
④P1067 两个 #define 把 return 0 拆成 unique2648 code; → 乙类展示形态命中宏展开合法、逻辑正确、300 组随机 0 不一致；按第 10 批 §3「展示形态且代码正确 → 归丙、不计数」乙类形态登记，不计命中
⑤P2089 int zl[50000][10] 作者自己说「可能不够」，3¹⁰=59049 会越界满足 sum==n 的方案数最大仅 8953（n=20），且 n∉[10,30] 时为 0；50000 绰绰有余不是 hack，归丙
⑥P1042 评论区「中间需要加空行」说明题解漏了空行逐字取回的代码里 11 分制末尾 cout<<w<<":"<<l<<endl 之后紧接 puts("")，官方要求的分隔空行已写；6 定点 + 200 随机 + 62525 字符长输入全对不是 hack，归丙

另有两次轻量自查：P1100 for(int i=1; a.size()<32; i++) 循环变量 i 从不使用、看着像只补一个 0（实测每轮长度 +1，300 组全对）；P1308 getchar() 与 getline 混用、tolower 直接传 char（题面字符集仅字母+空格，实测 300 组全对）。

本批再次印证：编译报错不等于题解有错——先分清是原文、还是我补的外壳 / 我写的独立解引入了问题。
