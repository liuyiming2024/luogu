2. 甲类 · P1098 l9bmtvor（两处独立缺陷）

2.1 代码（逐字取回）

cin>>p1>>p2>>p3; cin>>s; l=s.size();
cout<<s[0];
for(int t=1;t<l-1;++t){
    char a=s[t-1],b=s[t+1];
    if(p3==2){ x=b-1; y=a; k=-1; }   // 作者写了 p3=2 的逆序变量
    else     { x=a+1; y=b; k=1;  }
    if(s[t]=='-'&&s[t-1]<s[t+1]&&p3==1){   // ← 但外层把 p3=2 排除了
        ...  展开 ...
    }
    else cout<<s[t];
}
cout<<s[l-1];

作者明明准备了 p3==2 的 x=b-1, y=a, k=-1 和能跑 k=-1 的循环条件，结果外层 &&p3==1 把整条分支锁死：p3=2 时所有减号一律原样输出。

2.2 反例（题面 1≤p1≤3, 1≤p2≤8, 1≤p3≤2，长度 ≤100）

输入正确实际
2 3 2 / a-d-d（官方样例 #2）aCCCBBBd-da-d-d
1 2 2 / d-hdggffeehd-h
3 2 2 / a-da****da-d
1 2 2 / 1-5144332251-5
1 2 1 / a（长度 1，第二处独立缺陷）aaa

官方样例 #1 1 2 1 / abcs-w1234-9s-4zz 通过，所以是参数分支型缺陷，不是整体逻辑错。400 组随机 27 组不一致。

2.3 划界：为什么归甲不归乙

  • 修复不止一处。只删 &&p3==1（fix1）后重跑同样 400 组，仍有 12 组不一致，全是长度 1 的串（w → ww、9 → 99）——因为 cout<<s[0] 和 cout<<s[l-1] 在 l=1 时是同一个字符；再补 if(l==1) return 0;（fix2）才 0 不一致。
  • 一处是「整个参数分支被跳过」，另一处是「首尾字符输出缺特判」，两个独立缺陷，对应甲类判据里的「补分支」，不是「改一处字符或数字」。
  • 也不是主动防抄袭 / 乱搞形态（作者正文正经讲思路）。
若你想严格按「删一个条件就算一处」把它挪进乙，说一句我就改；这里按累计修复代价归甲。

3. 甲类 · P1098 zcy00qo9（漏一个子分支）

3.1 代码（逐字取回的展开段，补最小外壳）

if(p1==3)
    for(j=a[i-1]+1; j<=a[i+1]-1; j++) for(k=1;k<=p2;k++) putchar('*');
else if(p1==2){
    if(a[i-1]>='a'&&a[i+1]<='z'){          // 字母：p3==1 / p3==2 都有
        if(p3==1) for(...) putchar(j-'a'+'A');
        else if(p3==2) for(...) putchar(j-'a'+'A');
    }
    else                                    // ← 数字：只有顺序，p3=2 没逆序
        for(j=a[i-1]+1; j<=a[i+1]-1; j++) for(k=1;k<=p2;k++) putchar(j);
}
else if(p1==1){                             // p1=1：数字也做了 p3 判断
    if(p3==1) for(...) putchar(j);
    else if(p3==2) for(...) putchar(j);
}

题面写明 p1=2 时「这两种情况下数字子串的填充方式相同」，但 p3=2 的逆序对所有填充都生效。作者给字母补了 p3==2，给 p1==1 的数字也补了，唯独 p1==2 的数字分支漏了。

3.2 反例

输入正确实际
2 2 2 / 1-51443322512233445
2 5 2 / w2-mm9p1-6cuhh5pw2-mm9p1555554444433333222226cuhh5pw2-mm9p1222223333344444555556cuhh5p

对照全通过：官方样例 #1 / #2、1 2 2 / 1-5（p1=1）、2 2 1 / 1-5（p3=1）、2 2 2 / a-d（字母）、3 2 2 / 1-5（p1=3）、后继、连续减号、长度 1。400 组随机仅 1 组不一致，说明缺陷面很窄但真实存在。

3.3 划界

修复要插入 3 行（else if(p3==2) + 逆序双重循环 + putchar），不是改一个字符或数字；补完 400 组 0 不一致。按第 4 批「补分支 → 甲」归甲。

附：该篇大 if 条件里字母分支第 4 项写成了 a[i-1]<='z'（应是 a[i+1]<='z'），属笔误，但前面的混合类型 / 连续减号检查已保证两侧同类，实测无害 → 乙类登记，不计命中。

4. 丙类逐篇（4 篇）

4.1 P1044 g17kwzzm（两块代码都验）

  • 块 1 卡特兰卷积：f[0]=1; for(i=1..n) for(j=1..i) f[i]+=f[j-1]*f[i-j];
  • 块 2「智障递推」：dp[1][1]=1，j==0 → dp[i-1][1]，j==min(n,i) → dp[i-1][i-1]，否则 dp[i-1][j-1]+dp[i-1][j+1]，输出 dp[2*n][0]。

两块在 n=1..18 全枚举下都与 C(2n,n)/(n+1) 逐项一致（n=18 → 477638700），0 不一致。 我一度认定块 2 的 dp[i-1][i-1] 在 i-1>n 时读到未初始化列必错——实测不成立：那些高 j 状态剩余步数已不足以把栈降到 0，对 dp[2n][0] 贡献恒为 0。看似 bug 实则无害，记为自查。

4.2 P1044 rlz2fzsx

int a[36][18] 记忆化递归 f(p,s)，p==n*2 时判 s!=0，s>0 可 pop、否则 push，输出 f(0,0)。n=1..18 全枚举 0 不一致。 如实记一笔：a 第二维只有 18，而全 push 路径上 s 可到 18，存在越界读写；但把第二维改成 40 后结果完全相同，越界落在静态区且那些极端状态方案数为 0，未产生可观测错误。按「题面内确定性 WA/RE」口径归丙，仅登记为潜在风险——与第 7 批 P1003 9jadrxl0（同样数组偏小，但 n≥20000 真 SIGSEGV）正好形成对照：数组开小了不能凭直觉判，必须实测。
