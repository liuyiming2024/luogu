API 契约 · 只认 token 不认人

这是接口契约，供人工接入 Supabase / Webnote / 自建 Worker。 仓库不内置线上服务端，静态 Pages 无法持有密钥。 api/reference_server.py 是本地参考实现，默认不启动、不监听公网。

鉴权

Authorization: Bearer <token>

服务端只校验 token 是否匹配环境变量 LUOGU_API_TOKEN， 不校验自然人、不查 uid、不认账号名。token 不进仓库、不进前端代码， 只由使用者在浏览器「设置」里填入并存本地，或走 Actions secrets。

未带 / 错 token → 401 {"error":"invalid token"}。 写操作一律要求 token；读接口默认开放（可配置为也要求 token）。

评论持久化 · 直接推洛谷（第 9 条口径）

洛谷文章评论区是权威持久层，不另建评论数据库。 流程：

本地先存（离线可读）→ 待推队列 → POST /api/comments/push-luogu
   → 本机代理 / 自托管 runner / 浏览器扩展（持用户个人账号登录态）
   → 低频、人工确认、可关闭 → 洛谷 → 回写「已推洛谷」
  • 静态 Pages 绝不直接 fetch("https://www.luogu.com/...")：跨源 preflight、

HttpOnly + SameSite cookie、csrf-token 三重不可达（详见《架构可达性测试报告》）

  • 用用户个人账号；管理员账号不参与评论
  • 返回 queued 只表示已入队，前端状态仍是「待推」；

只有回传 pushed:true / state:"已推洛谷" 才标成功，不谎报

  • 失败进「失败待重试」，不轰炸重试；403/降级长退避
  • 本地副本始终保留，保证离线可看评论

约定

  • 所有写操作幂等：带 Idempotency-Key 或内容 sha，重复提交不产生副本
  • 时间统一 ISO8601 UTC；内容一律带 sha256 与 original_url
  • 删除资源：204 + 写一条「已移除」审计（对应隐私声明「源已删则本地也删」）
  • /api/publish 只在「已登录 + 联网 + 显式启用」时调用；

适配器内部仍走低频礼貌节奏，失败不重试轰炸

  • 前端 assets/local.js 未配置 apiBase 时全部走本地 localStorage，

零网络请求；配置了才按上表调用
