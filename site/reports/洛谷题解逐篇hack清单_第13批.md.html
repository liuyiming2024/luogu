2. 甲 · P2615 7p4p6gdm —— 初始化被注释吃了

逐字正文（搜索摘要与逐字取回一致）：

int n,a[40][40];
memset(a,0,sizeof(a));//初始化x,y
a[x][y]=1;

x, y 既没声明、也没赋值；唯一那行 memset 清的是数组 a，注释却写着 「初始化x,y」。题面要求「首先将 1 写在第一行的中间」，即 x=1, y=n/2+1。 按最小外壳补 int x, y;（全局零初始化，C++ 标准语义）后，a[0][0]=1， 整个幻方从 (0,0) 起算，输出相对标准答案整体平移一格。

输入期望实际
110
3（官方样例）8 1 6 / 3 5 7 / 4 9 27 0 5 / 0 4 6 / 3 8 0
517 24 1 8 15 …9 16 23 0 0 …
39标准 39 阶幻方平移矩阵

题面 1≤N≤39 且 N 为奇数，20/20 个合法 N 全部 WA。n=1 是最干净的最小反例。

四条路径对照（都补最小外壳，只差 x/y 初值）：

版本x/y 处理20 个 N 结果
逐字 + int x,y; 全局默认 020 组全挂
修复版 cin>>n; x=1; y=n/2+1;按题面0 不一致
照抄作者文字 x=n/2+1; y=1;行列写反19 组挂（n=1 恰好蒙对）
int x,y; 局部未初始化UB同样全挂

划界：补一行初值就能修好，代价接近乙；但根因是「初始化语句缺失 + 注释误导」， 与第 1 批 P1002 sfifnfaa（dp[0][0]=1 被循环覆盖）同型，且逐字代码确有 题面内确定性 WA → 归甲。想按修复代价挪乙，说一声。

有意思的是作者文字写「先初始化 x=n/2+1,y=1; 即1的位置」—— 行列本身写反了（代码分支里 x 是行、y 是列）。照抄文字反而 19 组挂。 所以修复必须以题面/分支语义为准，不能以思路文字为准。

3. 乙 · P1307 88t0yv7r —— 主动防抄袭（本批最典型的乙形态）

作者在正文末尾明写：「AC 记录 原来已经通过,现增加防抄袭内容,求通过。」 页面代码里夹了大量不可见 U+E00xx tag characters（󠄲󠅩󠄐󠄽…）。

  • 逐字版编译：error: ‘󠁐󠁉󠁣󠁔int’ does not name a type → CE。

按你的口径（代码只是辅助、缺头文件/展示形态不计缺陷）不算 hack， 且这正是乙类「主动防抄袭」的判定依据，单列。

  • 剥离不可见字符后的等价版：m = n%10 + m*10 标准整数反转，

负数先 cout<<"-" 再取绝对值。题面 −10⁹ ≤ N ≤ 10⁹， 317 组（16 个定点含 0/±10⁹/-380/100 + 300 随机 + 边界）0 不一致。

同类佐证：洛谷规范文章 zm6gqovk 明确写着 「不应在代码中加入防抄袭内容，如全角符号」，审核标准也写 「不要通过修改代码达到所谓『防抄袭』目的」。所以乙类是真实存在的形态， 但我只按文本归类，不指认谁故意埋坑。

6. 差点误判 / 自查（本批 4 次）

  1. 我漏抄了 cin>>n;（最悬的一次）：第一版 7p4p6gdm 源码没有读入 n，

局部 n 未初始化，输出循环 i<=n 直接不进 → 四个 P2615 版本全部空输出、 20 组假 WA，连修复版都挂。手动 echo 3 | ./exe 才看出来， 回原文/题面复核补回读入语句，结果与第 5 批 P1164（漏抄 dp[i][0]=1）同型。

  1. 修复版初值顺序：x=1; y=n/2+1; 必须在 cin>>n 之后，

放在之前等于用未初始化的 n 算列号。第一版就是这么错的。

  1. 行尾空格：逐字版输出 cout<<a[i][j]<<" " 每行末尾带空格，

题面只要求「相邻两个整数之间用单空格隔开」。按第 9 批 P1598 口径 逐行 rstrip 后比较，不把格式差异当 WA。

  1. 不可见字符：tag characters 逐字编译 CE，但按口径不计缺陷；

剥离后核心逻辑正确 → 乙，不是甲。

纪律再补一条：补外壳时「读入语句」和「依赖读入的初值」必须一起复核顺序。
