数据库令牌接入方案（第 15 条 · 预留位）

当前状态：未接入。 你还没给数据库信息，所以本文件只定义契约， tools/token_store.py 默认关闭、不发任何请求。 不编造接口、不假装已连库、我不接收任何 token 明文（与第 14 条一致）； token 值由本人自己写进库，别发在对话里。

这件事解决什么

第 14 条里，本人要一次性填 5 个 Secret（cookie / csrf / uid / 端点 / consent）。 你说「可以给我一个数据库供你存储 token」——那就把值挪进你的库： 本人自己把 token 写进库，Action 从库读，Secrets 里只剩 1 个 DB 只读访问凭据。

无数据库（现状）接库后
本人要填的 Secret5 个洛谷值1 个 DB 只读凭据
token 值放哪Settings Secrets你的数据库（本人自行写入）
consent 由谁确认本人写 Secret仍必须留 Secret（当前 gate 只读它；想放库需另改 gate）
我在对话里收明文不收仍不收

1 个凭据不能降为 0（除非库匿名可读，那不安全，不做）。这 1 个可以用 GitHub 的加密接口代写进 Secrets，不用你进 Settings 页面——但「值」仍由你给、 或由你在库里授权，我不会替你确认自担后果。

表结构建议（最小）

create table luogu_tokens (
  name        text primary key,   -- 键名，见下方白名单
  value       text not null,      -- 值；建议列级加密或只存短期凭据
  updated_at  timestamptz default now()
);

只往 name 写这些键（写别的会被忽略，不会污染运行时）：

LUOGU_COOKIE、LUOGU_CSRF、LUOGU_UID、LUOGU_SUBMIT_ENDPOINT、 LUOGU_IDE_ENDPOINT、LUOGU_SUBMIT_CONSENT

安全提醒：把洛谷登录态放第三方库 = 多一份托管风险。建议开 RLS、 只给 runner 一个只读角色、值列加密、定期轮换。 LUOGU_SUBMIT_CONSENT 当前必须留在 Secret：工作流的 gate 在 shell 里只读 secrets.LUOGU_SUBMIT_CONSENT，库里的值它看不见。真要把 consent 也放库， 得把 gate 改成 Python 判定（接库时一并做）。让「自担确认」这一下始终在你手里， 也符合第 14 条。

已定义的两种后端

tools/token_store.py 只认这两种，其余明确回退，不做成假功能：

后端需要的环境变量读法
supabaseLUOGU_TOKEN_SUPABASE_URL、LUOGU_TOKEN_SUPABASE_KEY、LUOGU_TOKEN_TABLEPostgREST GET /rest/v1/{table}?select=name,value（urllib，无需额外包）
sqlLUOGU_TOKEN_DSN（postgresql:// / mysql://）、LUOGU_TOKEN_TABLE惰性 psycopg / pymysql，缺驱动即安全回退

开关：LUOGU_TOKEN_STORE=1 + LUOGU_TOKEN_BACKEND=supabase|sql。 不设就完全关闭，主链路行为与现在一模一样（tools/verify_submit.py 已回归验证）。

安全约束（写死在代码里）

  • 默认关闭 → 返回空，不联网、不导入驱动、不打印
  • 只补空键：Secrets 里显式给的值优先，库不会覆盖
  • 白名单键；表名做 [A-Za-z_][A-Za-z0-9_.]* 校验，阻断拼接注入
  • 日志只出现键名；异常只打印类型名（DSN 可能含口令，不外泄）
  • 端点按洛谷当前页面填，仓库不编造内部 API
  • 低频、降级即停、幂等、失败不轰炸重试等纪律不变

你给我什么就能接（一句话即可，不用再做选择题）

  1. 后端类型：supabase 还是 sql
  2. 连接信息：Supabase 项目 URL + 只读 key，或 DSN；以及表名 / 键名列名 / 值列名
  3. 一个只读访问凭据（我可用加密接口代写进 Secrets，或你自己在库里建只读角色）
  4. 你自己把 token 值写进库（别发在对话里）
  5. LUOGU_SUBMIT_CONSENT 由你确认后留在 Secret（gate 只读它）
