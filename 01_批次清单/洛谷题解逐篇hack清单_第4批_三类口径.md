## 0. 口径更新（本批起固定）

### 代码只是辅助，不判「全不全」

题解作者本来就没有被要求贴出完整可提交代码。因此：

- 取到代码片段时，我**补最小外壳**（`#include`、`int main` 返回类型、必要全局变量声明）后再编译；
- **补齐的部分一律不计入题解缺陷**；
- **只验证核心逻辑对不对**，不评判代码完整不完整。
- 由此，前几批里「缺头文件 CE」「老式 `main(){}`」「页面渲染吞字符」**不再作为缺陷判定**，统一移到乙类记一笔。

### 三类定义

| 类 | 名称 | 判据 |
|---|---|---|
| **甲** | **已 hack** | 题面内存在**确定性**测试点使代码 WA/RE；且修复要动算法层面（移动语句、换类型、补分支、重写判断），不是改一个字面量能救回来的 |
| **乙** | **轻微笔误 / 主动防抄袭**（单列） | 代码文本有偏差，但**改一处字符或数字即逻辑正确**；或作者主动删减、拆段、声明为示意版、埋坑。**列出，但不计入 hack 命中** |
| **丙** | **未 hack** | 核心逻辑正确，反例搜索未命中 |

甲类的其余三条硬约束不变：题面范围内、不看评测机波动（不主张 TLE/超时）、结果可复现。

**乙类归并依据**：洛谷题解审核标准明文写有「**不要通过修改代码达到所谓『防抄袭』目的**」「**洛谷有反作弊系统，请各位写题解的时候不要再加各种坑了**」，说明这类文本偏差是真实存在的现象。但我**只按文本形态归类，不臆测作者动机**——不指认某篇"就是故意埋坑"。

### 2.1 P4995 `up402yw6` · 丙

补最小外壳后核心（逐字）：

```cpp
#define int long long
int h[300 + 9];
sort(h + 1, h + n + 1);
int lt = 1, rt = n, t = 0, now = 0;
for (int i = 1; i <= n; i ++) {
    if (i % 2 != 0) { t += (now - h[rt]) * (now - h[rt]); now = h[rt]; rt --; }
    else            { t += (now - h[lt]) * (now - h[lt]); now = h[lt]; lt ++; }
}
cout << t;
```

**独立正确解**：状压 DP `dp[mask][last]` 枚举全部跳跃顺序求最大值，**不依赖贪心结论**。
样例 1 `2 / 2 1` → 5 ✓；样例 2 `3 / 6 3 5` → 49 ✓；n=1 → 10000 ✓；**120 组随机（n≤9）0 不一致**。
数组 `h[309]` 对题面 `n ≤ 300` 刚好够，`#define int long long` 也挡住了 `h ≤ 10⁴` 时平方和约 `3×10¹⁰` 的溢出；n=300 上界跑通。

### 2.2 P1216 `tneoku44` · 丙

```cpp
int a[1001][1001],n;
for(int i=0;i<n;i++) for(int j=0;j<=i;j++) cin>>a[i][j];
for(int i=n-1;i>0;i--) for(int j=0;j<i;j++) a[i-1][j]+=max(a[i][j],a[i][j+1]);
cout<<a[0][0];
```

0-based 下三角存法 + 自底向上原地累加，与标准 DP **120 组随机（含 n=1000）+ 全 0 / 全 100 边界 0 不一致**。数组对 `r ≤ 1000` 够用，`int` 对值 ≤100 够用。

## 3. 乙类清单（单列，不计 hack）

### 3.1 P1018 `pmio8se0` — off-by-one 笔误（自甲类移入）

`if(n-xx-1<v) return;` 应为 `n-xx`。改前 300 组合规随机 63 组 WA（`6 1 / 123456` 期望 74070、实际 69104；`k=n-1` 输出空串），**改后 300 组 0 不一致**。DP 思路、剪枝框架、高精度乘法 `add()` 本身都正确。

### 3.2 P1002 滚动数组版 — 数组尺寸笔误（本批新增）

```cpp
long long f[23];
bool ma[23][23];                    // ← 坐标 +2 后马控制点最远到 (24,24)
void work(long long x,long long y){ ... ma[x+2][y+2]=true; ... }
```

`ma` 下标 0..22，但 `x+2` 可达 24，越界写踩到后面的 `f[]` → 题面内确定性 WA：

| 输入 | 期望 | 实际 |
|---|---|---|
| `10 15 20 13` | `3268760` | `5230016` |
| `8 9 20 15` | `24310` | `843485500` |
| `18 10 20 20` | `13123110` | `3495893927489421862` |

400 组随机中 16 组不一致。把 `ma[23][23]` 改成 `ma[27][27]`（**只改一个数字**）后，剩余 2 组不一致全是「马控制起点」——违反题面「保证起点不是马的控制点」，**题面合法范围内 0 不一致**。反例仍列出，但不计入甲类。

### 3.3 P1018「不带高精度」示意代码篇 — 主动简化的辅助代码（本批新增）

作者原文：「**为方便理解附上一个不带高精度的代码**。带高精度的写法建议用类类型或者结构体并重载运算符实现」，代码为 `long long dp[N][N]`。N≤40 时结果远超 `long long`，必然溢出——但作者已明说这是思路示意、不是完整解法。按本批新口径：**这是辅助代码，不拿类型不够去 hack 它**，归乙类。
