## 2. 甲类 · P1421 `dk5mkxij`（本批唯一命中）

### 2.1 题解代码（按作者分段提示拼装）

文章把代码拆成 6 段给（「中间部分在下面」「循环到没钱」「买一支就扣一次钱」），按提示顺序拼成：

```cpp
#include <bits/stdc++.h>
using namespace std;
int main(){
    double a,b;
    int sum=0;
    cin>>a>>b;          // a 元 b 角
    b=b/10;             // 角换算成元
    a=a+b;              // 总钱数
    while(a>=1.9){      // 循环到没钱
        a=a-1.9;
        sum++;
    }
    cout<<sum<<endl;
    return 0;
}
```

按「代码只是辅助、不判全不全」，拆段展示本身不是缺陷；**只验拼装后的核心逻辑**。

### 2.2 反例（题面 `0≤a≤10^4, 0≤b≤9`，完全合规）

| 输入 | 正确 | 实际 | 说明 |
|---|---|---|---|
| `7 6` | `4` | `3` | 7 元 6 角 = 76 角，76/19 = 4 支 |
| `19 0` | `10` | `9` | 19 元整，190/19 = 10 支 |
| `20 9` | `11` | `10` | 209/19 = 11 支 |

**独立进程复核**：编译真正拼装版跑上述输入，输出与内部对拍一致。官方样例 `10 3 → 5`、`1 9 → 1`、`3 8 → 2` 都通过，说明不是整体逻辑错，而是**恰好整除时边界比较提前 false**。

**全枚举**：`a=0..10000, b=0..9` 共 **100010 组，2031 组不一致**。规律很清楚：当 `10a+b` 是 19 的倍数时，`double` 累减的舍入误差让最后一次 `a>=1.9` 判成假，少买一支。独立正确解 `(10*a+b)/19`（整数除法）。

### 2.3 划界说明（甲乙边界，写清楚免得以后翻案）

- 事实：把比较改成 `while(a>=1.9-1e-9)` 后，同样 100010 组 **0 不一致**。
- **仍归甲**，三条理由：
  1. 根因是 **`double` 表示货币并反复累减**的类型选择错误，根本修复是换成整数角运算 `(10a+b)/19` —— 正对应甲类判据里的「换类型 / 重写判断」；
  2. 加 eps 不是修正笔误，而是**引入新的容差语义**，且只对本题这个数值范围成立，换个精度/编译器不保证；
  3. 作者正文明确写「把总钱数存到 a 里（**所以用 double**）」——是**有意的设计选择**，不是笔误，也不是防抄袭/乱搞形态，因此不进乙类。
- 若你想严格按「改一处表达式即修复」的字面判据把它挪进乙，说一句我就改。

> 对照：同题另有多篇用整数 `c=a*10+b; printf("%d",c/19);` 的题解，全枚举/抽样均正确（未取到 lid，仅作内部对照，不纳入计数）。

## 3. 乙类 · P1003 `9jadrxl0`

### 3.1 代码与题面冲突

```cpp
int im[10020][4];                       // ← 题面 n ≤ 10^5
...
for(int i=n;i>=1;i--)
    if(im[i][0]+im[i][2]>=x && im[i][1]+im[i][3]>=y && im[i][0]<=x && im[i][1]<=y){
        ans=i; break;
    }
```

覆盖判断本身（含边界取等、倒序找最上层）**完全正确**；问题只在第一行的数组尺寸。

### 3.2 实测（很值得记的「部分 n 不出错」现象）

| n | 期望 | 原版 | 改成 `im[100005][4]` |
|---|---|---|---|
| 10021 | 10021 | `10021`（rc 0） | `10021` |
| 10050 | 10050 | `10050`（rc 0） | `10050` |
| **20000** | 20000 | **空输出，rc −11（SIGSEGV）** | `20000` |
| **100000** | 100000 | **空输出，rc −11（SIGSEGV）** | `100000` |
| 1 / 5 / 100 | −1 | −1 | −1 |

`im` 是全局数组，n 略超 10020 时越界写落在 BSS 空白里，读写同址、结果仍对；n 大到一定程度才踩到不可访问页而 RE。**所以「数组开小了」不能凭直觉判定，必须实测**——这也是历批纪律的又一次应用。

### 3.3 为什么归乙

把 `10020` 改成 `100005` —— **只改一个数字**，全部用例恢复正确。按第 4 批对 P1002 `ma[23][23]` 的同一处理，归乙类单列、不计甲类命中；反例只作验证数据。
