### 3.2 P1002 过河卒 — `sfifnfaa` · **已 hack**

题解 C++ 核心（逐字）：

```cpp
int countPaths(int n, int m, int horse_x, int horse_y) {
    vector<vector<int>> dp(n+1, vector<int>(m+1, 0));
    dp[0][0] = 1;
    for (int i = 0; i <= n; i++) {
        for (int j = 0; j <= m; j++) {
            if ((i-2 == horse_x && j-1 == horse_y) || (i-1 == horse_x && j-2 == horse_y)) {
                dp[i][j] = 0;
            } else {
                dp[i][j] = (i > 0 ? dp[i-1][j] : 0) + (j > 0 ? dp[i][j-1] : 0);
            }
        }
    }
    return dp[n][m];
}
```

**反例数据（可直接投喂）**

```
6 6 3 3
```
期望 `6`（官方样例），实际 `0`。

```
20 20 0 20
```
期望 `137846521561`，实际 `0`。

```
20 20 10 10
```
期望 `21388094780`，实际 `0`。

**被卡原因（三处叠加，任一处都足以 WA）**

1. **起点被自己抹掉**：`dp[0][0]=1` 之后，循环第一轮 `i=0,j=0` 走 `else`，`(i>0?…:0)+(j>0?…:0)=0`，直接把起点覆盖成 0，整张表恒为 0。这是"任何输入都输出 0"的直接原因，官方样例都过不了。
2. **马控制点只判了 2 个**：条件只覆盖 `(hx+2,hy+1)` 与 `(hx+1,hy+2)` 两格，漏掉另外 6 个日字点、**马自身所在格**，也没做坐标越界保护。
3. **`int` 溢出**：`vector<vector<int>>`，n=m=20 时答案量级 `C(40,20)≈1.38×10^11`，必须 `long long`。

> 附带发现：题解同页还给了 Python 版，逻辑相同，同样在起点被清零，Python 无溢出但依旧全 0。

### 3.4 P1220 关路灯 — `uezud59i` · 约束内未 hack，但有条件性缺陷

题解用 DFS + 剪枝，核心：

```cpp
long long n,m,minn,s;
long long a[100001],b[100001];
void dfs(int i,int j,int k,int v,int x){
 if (v>minn) return;
 if (i==1 && j==n) { if (v<minn) minn=v; return; }
 ...
}
int main(){ cin>>n>>m; minn=1000000000; ... dfs(m,m,0,0,s); cout<<minn; }
```

- 官方样例 `5 3 / 2 10 / 3 20 / 5 20 / 6 30 / 8 10` → 期望 `270`，实际 `270`。
- 12 组随机小数据（n=2~8）与区间 DP、记忆化暴力三方一致，**题面 `a_i ≤ 100, b_i ≤ 100, n ≤ 50` 约束内未找到反例**。

**条件性缺陷（明确不计为合法 hack）**：`minn` 硬编码 `1e9`，DFS 的 `v/x` 又是 `int`。若把坐标放大到题面之外，最优解超过 `1e9` 时会被上界截断：

```
5 3
0 100
1000000 100
2000000 100
3000000 100
4000000 100
```
独立正确解（区间 DP 与记忆化暴力均为 `800000000`），题解输出 `1000000000`。

该输入刻意突破 `a_i ≤ 100`，**不能作为洛谷合法 hack 数据**，仅用于说明"题解依赖数据上界而非算法上界"。

### 3.5 P3959 宝藏 — `l6u32sp7` · 未 hack，但无正确性保证

题解自述"普通贪心是错的"，改用固定种子 `srand(19260817)` + `randtime=25000` 次随机交换边序跑 Kruskal，取最小。

验证方式：
- n=5：Prüfer 序列枚举**全部**生成树，对每个根算精确最优，60 组随机连通图未出现差异；
- n=8~10：40 组随机图、每组采样 12000 棵生成树找"比题解输出更小的合法解"，未找到。

**结论**：不能判为已 hack，但这不是正确算法——固定种子使其结果确定，是否存在反例取决于是否恰好覆盖到最优生成树；数据一大（n≤12）没有穷举保证。属于"能 AC 但不该写进题解区当正解"的骗分/随机化解法。若后续要 hack，方向是构造**最优生成树不是 MST、且边权差异大**的图（题解只在 MST 里枚举根）。

> 补充：题解代码里 `std::swap(kruskalEdge[rand(1,kcnt)], ...)` 用的是自定义 `rand(l,r)` 而非 `std::rand`，按题解文字描述补全是必要前提。

### 3.6 P5179 Fraction — `siyuan` · 未 hack

类欧几里德递归解，`long long`。

- 161 组合法区间（`a/b < c/d` 的小数据）与"最小分母穷举"独立解逐字一致；
- 4 组 `10^9` / `10^18` 大数（含 `a/b` 与 `c/d` 极接近的窄区间），输出均验证为**落在开区间内的最简分数**，例如 `1 10^9 2 10^9` → `1/500000001`；
- 中途曾误把 `a/b ≥ c/d` 的非法区间也拿去比（此时题目无解，输出什么都没有意义），剔除后 **0 处不一致**。

**无反例**。这是本批质量最高的一篇。
