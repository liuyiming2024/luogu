## 0. 判定口径（本轮起固定）

**「hack 成功」必须同时满足：**

1. 反例输入**严格落在题面给出的数据范围内**；
2. **不考虑评测机波动**——不主张 TLE、不主张临界超时、不主张随机化带来的时间抖动；
3. 存在**确定性**测试点，使题解代码 **WA / RE**（输出值与独立正确解不符，或确定性崩溃）；
4. 结果可复现：同一份代码、同一份输入，输出固定。

按此口径，**"代码有坏味道"「随机化没有正确性保证」「换台机器可能超时」「越界数据能卡掉」一律不算 hack**。

## 3. 逐篇详情

### 3.1 P1182 `arorhglg` · **已 hack**（int 上界溢出）

题解逐字代码（关键部分）：

```cpp
int n,k;
int l,r,m;                    // ← 二分上下界是 int
long long t,tot,a[10000001];
inline bool judge(int x){ ... return tot>=k; }
int main(){
    scanf("%d%d",&n,&k);
    for(int i=1;i<=n;i++){
        scanf("%d",&a[i]);   // 格式符与 long long 不匹配（见下注）
        r+=a[i];             // ← 累加所有 Ai，可超 2³¹-1
        if(a[i]>l) l=a[i];
    }
    while(l<=r){ m=l+(r-l)/2; t=0,tot=0; if(judge(m))l=m+1; else r=m-1; }
    printf("%d",l);
    return 0;
}
```

**题面约束**：`1 ≤ N ≤ 10⁵`，`M ≤ N`，`Ai < 10⁸`，**答案不超过 10⁹**。注意：题面**没有限制 ΣAi**。ΣAi 可以轻松到 `10⁵ × 10⁸ = 10¹³`，而 `r` 是 `int`。

另一篇 P1182 题解实测提到「这组数据所有整数之和大约是 2.5×10⁹」，且该题解页挂有管理组提示「实现上二分边界有问题，应当使用 long long」——说明洛谷真实数据里就存在这种点。

**反例（题面内、确定性 WA）**

```
100 50
30000000 30000000 ... （共 100 个 30000000）
```
- 合规性：N=100 ≤ 10⁵ ✓，M=50 ≤ N ✓，Ai=3×10⁷ < 10⁸ ✓，答案 6×10⁷ ≤ 10⁹ ✓
- ΣAi = 3×10⁹ > 2³¹−1 → `r` 溢出为负数 → `while(l<=r)` 一次都不进 → 直接输出 `l = 30000000`
- 独立正确解（long long 二分）：每段最多 2 个，共 50 段，**答案 60000000**
- 题解实际输出 `30000000`

另两组同样命中：

```
100000 50000
25000 25000 ... （共 100000 个 25000）   → 期望 50000，实际 25000

100000 50000
30000 30000 ... （共 100000 个 30000）   → 期望 60000，实际 30000
```

**对照组（证明是溢出而非逻辑错）**：官方样例 `5 3 / 4 2 4 5 1` → 6 ✓；不溢出的 `100 50` + 100 个 `25000`（Σ=2.5×10⁶）→ 50000 ✓。

> 注：`scanf("%d", &a[i])` 写入 `long long` 是 UB（编译有 `-Wformat` 警告）。本环境里 `a[]` 是全局 BSS 清零，正的小整数写入低 4 字节后高位仍为 0，因此**该 UB 在此处碰巧无害**；导致 WA 的确定性主因是 `int r` 溢出。附带一提 `a[10000001]` 是 `long long`，占 80MB BSS，属于浪费但不作为 hack 依据（内存限制属资源约束，不按本口径计入）。

### 3.2 P1002 `yk90rg78` · **已 hack**（起点初始化在递推之后）

题解逐字代码（语句顺序原样保留）：

```cpp
long long f[MAXN][MAXN]={0};
int ctrl[MAXN][MAXN],n,m,hx,hy;
int main(){
	cin>>n>>m>>hx>>hy;
	for(int i=0;i<9;i++){ /* 标 9 个控制点，含马自身 */ }
	for(int i=0;i<=n;i++)
		for(int j=0;j<=m;j++){
			if(ctrl[i][j])continue;
			if(i!=0)f[i][j]+=f[i-1][j];
			if(j!=0)f[i][j]+=f[i][j-1];
		}
	f[0][0]=1-ctrl[0][0];     // ← 在整张表算完之后才赋值
	cout<<f[n][m];
	return 0;
}
```

**被卡原因**：`f[][]` 全局清零，DP 双重循环以 `f[0][0]=0` 起步，整张表递推完仍全为 0；循环结束后才把 `f[0][0]` 改成 1，**对 `f[n][m]` 已无任何影响**（除非 n=m=0）。所以除退化情形外输出恒 0。

**反例（题面内、确定性 WA）**

| 输入 | 期望 | 实际 |
|---|---|---|
| `6 6 3 3`（官方样例） | `6` | `0` |
| `20 20 0 20` | `137846521561` | `0` |
| `20 20 10 10` | `21388094780` | `0` |

（`1 1 0 0` 期望 0、实际 0，属巧合命中，不作为反例。）

> 与第 1 批 `sfifnfaa` 是**不同题解、不同 bug**：`sfifnfaa` 是起点被循环第一轮自己覆盖成 0 + 只判 2 个控制点 + `int` 溢出；`yk90rg78` 是初始化语句位置错误。同一道题两篇独立题解都被官方样例卡掉。

### 3.3 P1002 `vis` 标记版 · 未 hack

```cpp
memset(vis,true,sizeof(vis));   // true = 可走
cin>>n>>m>>a>>b; n+=2,m+=2,a+=2,b+=2;
for(int i=1;i<=8;i++) vis[a+x[i]][b+y[i]]=false;
vis[a][b]=false;
dp[2][1]=1;
```

### 3.4 P1216 `ove5v8ck` · 未 hack（附一处展示缺陷）

题解给了两份代码：

- **自底向上版**：`for(int i(n-1);i>0;--i) for(int j(1);j<=n;++j)` 内层写成 `j<=n`（应为 `j<=i`），多算无用列并有一处 `dp[i+1][j+1]` 越界读。但 `dp[1][1]` 的依赖链只经过 `j ≤ i` 的有效格，垃圾值不影响答案。**120 组随机 + 全 0 / 全 100 边界 + n=1000，0 处不一致**。
- **自顶向下版**：补上必要头之后逻辑同样正确，0 处不一致。

**展示缺陷（不计 hack）**：第二份代码块逐字编译会 **CE**（缺 `#include <iostream>` 与 `<algorithm>`，`cin/cout/max` 未声明）。但这是代码不完整、且与输入无关——按本轮口径「存在测试点使代码无法通过」要求反例是**数据**，CE 属于任何输入都失败的展示问题，故只记录、不列入反例清单。
