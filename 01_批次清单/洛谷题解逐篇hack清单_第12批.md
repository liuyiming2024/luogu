## 2. 甲类 · 4 篇逐条

### 2.1 P1618 `ehkpairy` —— A=0 除零

逐字源码含 `red()`（把 A:B:C 化为最简）、`finish()`（1~9 各一次）与
`for (int i = 100 + a - 100 % a; i <= 999; i += a)`。题面明确 `0 ≤ A < B < C ≤ 999`，
**A 可以为 0**；此时 `100 % a` 是整数除零，`red()` 里 `a==1` 不成立、
`for(i=a; i>1; --i)` 也不进，a 保持 0。

| 输入 | 期望 | 实际 |
|---|---|---|
| `0 1 2` | `No!!!` | SIGFPE（rc −8） |
| `0 2 3` | `No!!!` | SIGFPE |
| `0 1 10` | `No!!!` | SIGFPE |

1399 组（C(21,3) + 60 组随机 + 9 组构造）里 **12 组不一致，全部 A=0**；
`1 2 3` 官方样例等其余 1387 组全对。**修复版**（`scanf` 之后补
`if(a==0){printf("No!!!");return 0;}`）1401 组 **0 不一致**。

划界：修复只需补一个分支，代价接近乙；但根因是**未处理题面明确允许的 A=0 边界**
（不是笔误），且「补分支」在三类口径里明确归甲。若按修复代价想挪进乙，说一声。

> 自查记一笔：第一版修复我把特判误放在 `scanf` 之前，a 还是全局零值，
> 造出 38 组假 WA。特判位置回到读入之后才归零——**修复版本身也要复验**。

### 2.2 P1618 `j4zpxmp6` —— 整除门槛漏解

逐字源码三重枚举 `num1 = i*100+j*10+k`，随后 `if (num1 % a) continue;`
、`num2 = num1/a*b`、`num3 = num2/b*c`。比例 `A:B:C` 的公因子 t **允许是分数**：
只要 `num1·B` 与 `num1·C` 能被 A 整除即可，不要求 `num1` 被 A 整除。
题面**没有保证 A:B:C 是最简比**（还注明 2022.8.3 新增过 Hack 数据）。

| 输入 | 期望 | 实际 |
|---|---|---|
| `2 4 6` | 4 行（192/219/273/327 组） | 只有 `192 384 576` |
| `5 10 15` | 4 行 | `No!!!` |
| `6 14 16` | `213 497 568` / `321 749 856` | `No!!!` |
| `2 6 10` | `129 387 645` | `No!!!` |

1399 组里 **10 组不一致**，全是非最简比例。**修复版**必须去掉三个整除门槛、
改用 `n1*b%a / n1*c%a` 交叉相乘并重写 num2/num3 计算——1401 组 **0 不一致**。
`ehkpairy` 因用 `red()` 先化简比例，同批所有非最简输入反而全对，构成同题对照。

### 2.3 P1469 `iv10492z` —— 题面 8 Mb 限制下的确定性 RE

逐字源码 `vector<int> p; p.resize(n+1);` 再做前缀异或 `p[i]=p[i]^p[i-1]`。
**逻辑正确**（61 组本地对拍 0 不一致），但题面 `1 ≤ n ≤ 10⁷+1` 且
「空间限制 8 Mb」，vector 需要 `4(n+1)` 字节 ≈ 40 MB。

静态编译 + `RLIMIT_AS` 对照实验（输入 n=3000001，全部 1 成对 + 落单 2，题面内）：

| 限制 | `iv10492z` 静态版 | 静态 O(1) 异或对照版 |
|---|---|---|
| **8 MB（题面）** | **rc −6（SIGABRT / bad_alloc），空输出** | rc 0，输出 `2` |
| 16 MB | rc 0，输出 `2` | rc 0，输出 `2` |
| 32 MB | rc 0，输出 `2` | rc 0，输出 `2` |

同限制下对照版正常 → 不是「限制太死谁都跑不了」，是 O(n) 空间本身。
修复必须删掉 vector、改成单变量累积异或（重写循环体）→ 甲类。
与第 10 批 P1152「10 MB 局部数组爆栈」同型。

> 口径边界：这条是**题面空间限制下的确定性 RE**（不是 TLE、不是评测机波动）。
> 本地无限制时它输出正确；若你的口径只认 WA/RE 数值错、不把 MLE 计入，
> 这篇可挪丙，说一声。另：沙盒无 `/usr/bin/time`，且 `fork` 继承父进程页会让
> `ru_maxrss` 虚高，故峰值 RSS 不作为证据，只采用 RLIMIT_AS 对照。

### 2.4 P1469 `utz61eus` —— 桶越界 + 遍历截断

逐字源码 `int a[100000005]`（约 400 MB 全局）配 `a[k]++`，末尾
`for(int i=1;i<=10000000;i++)` 找 `a[i]==1`。题面 `1 ≤ aᵢ ≤ 10⁹`，且只有一只落单。

| 输入 | 期望 | 实际 |
|---|---|---|
| `3 / 2 2 9999999` | `9999999` | `9999999`（对） |
| **`3 / 2 2 10000001`** | **`10000001`** | **空输出（WA）** |
| `3 / 2 2 50000000` | `50000000` | 空输出（WA） |
| `3 / 2 2 100000000` | `100000000` | 空输出（WA） |
| **`1 / 1000000000`** | **`1000000000`** | **SIGSEGV（rc −11）** |
| 官方样例 `9 / 2 2 1 3 3 3 2 3 1` | `2` | `2`（对） |

三层独立缺陷：① 落单值 >1e7 时末尾遍历根本扫不到；② `aᵢ > 1e8` 时
`a[k]++` 下标越界（1e9 → 4 GB 偏移）直接崩；③ 400 MB 数组本身远超题面 8 Mb。
最干净的反例是 `3 / 2 2 10000001`——不依赖崩溃、纯逻辑漏输出。修复必须重写核心。

## 3. 丙类 · 4 篇

  纪律不计；另实测等价版 `int a[1000001]` 在 n=1000001 越界写 **未崩**
  （落在 BSS 空白、读写同址），与第 7 批 P1003 现象一致——

  系页面吞字符，补最小外壳，不计缺陷。
- **P1046 `d8583wuv`**：`height+30>=a[i]`，304 组（含全 100 / 全 300 / 130 边界）0 不一致。
  正文片段 `for` 起止被页面吞字符，按题解文字补全循环体。
- **P5015 `qajlal91`**（本批新增编号）：`getline(cin,n,'\n')` 逐字符判 `!=' '`，

## 4. 差点误判 / 自查（本批 4 次）

1. **对拍脚本自身超时**：P1618 独立解写成「9! 个排列 × 1399 组」逐组扫，
   约 5 亿次 Python 循环把沙盒跑挂。改为「最简比例 → 全部解」预建索引，
   `gcd(A,B,C)` 查表，复杂度降到 O(1)。
2. **编译全挂**：`g++` 命令里混进空字符串参数，ld 报 `cannot find :`，
   9 个程序全部 rc=1；同时目录变量 `B` 被 P1618 循环变量 `B` 覆盖成整数。
   两处都是我的脚手架，与题解无关。
3. **修复版假 WA**：`a==0` 特判放在 `scanf` 之前（§2.1）。
4. **内存测量**：`ru_maxrss(RUSAGE_CHILDREN)` 是累计最大值、
   `fork` 又继承 Python 父进程页，两版都读成 180.8 MB；
   且沙盒无 `/usr/bin/time`。改用**静态编译 + RLIMIT_AS 对照**才拿到干净结论。

纪律补两条：**修复版本身也要复验**；**资源类结论必须有同限制下的正确解对照**。
