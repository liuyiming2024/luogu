## 2. 乙 · P1098 `88laurj5` —— 一个数字写错

逐字取回的完整代码里，p3==1 / p1==2 的**数字**分支是：

```cpp
for(char j=a[i-1]-31; j<a[i+1]-32; j++)
  for(int k=1;k<=p2;k++)
    if(/* 数字 */) cout<<char(j+30); else cout<<char(j);
```

而同一篇里 p3==2 / p1==2 的逆序分支写的是 `cout<<char(j+32)` —— **两处不对称**。
`1-5` 展开时 j=18,19,20，`j+30` 得到 `'0','1','2'`，`j+32` 才是 `'2','3','4'`。

| 输入 | 期望 | 实际 |
|---|---|---|
| **`2 2 1 / 1-5`**（p1=2, p2=2, p3=1） | `12233445` | `10011225` |
| `2 1 1 / 1-5` | `12345` | `100125` |

415 组对拍（15 个定点 + 400 组随机 p1∈[1,3] / p2∈[1,8] / p3∈[1,2]，
串含字母数字减号）**只 1 组不一致**——缺陷面极窄：必须同时满足
p1=2、p3=1、数字区间、顺序展开。但确实是题面内确定性 WA。

**修复版**只把 `j+30` 改成 `j+32`（一个字符），415 组 **0 不一致** → **乙类**。

划界与第 8 批同题 `zcy00qo9` 形成对照：那篇是 p1==2 数字分支**整个逆序分支缺失**，
要插 3 行代码 → 甲；这篇只是常量笔误，改一个数字 → 乙。修复代价判据保持一致。

> 自查：`j+30` 看着像「页面把 32 吞成 30」，但两次逐字取回的正文一致，
> 且同篇 p3==2 分支明确写 `+32`，所以按「原文如此」处理，归乙不归丙。

## 4. 保存站实测（本轮重点，详见独立记录）

| 通道 | 端点数 | 结论 |
|---|---|---|
| curl 直连 luogu.me 首页 / article / api / help / 无 www / query | 7 | **全 403** `policy_default_denied` |
| curl 直连 luogu.com/article | 1 | **403**（同一策略层） |
| 内置通道 luogu.me 首页 | 1 | 可读，仅公告与站点说明 |
| 内置通道 luogu.me 文章 / articles / square / statistics / help / search | 6 | **全是 SPA 骨架**，无任何 8 位编号、无正文 |
| 内置通道 luogu.com/problem/.../solution | 1 | 无法获取（需登录） |
| 内置通道 luogu.com/article/<lid> | 4 | **可用**，本轮逐字取回 4 篇完整代码 |

保存站首页逐字引用：
> 「近期有大量 AI 自动化程序不断请求保存 API,导致队列堵塞。」
> 「我们正在实现合适的解决方案。」

所以「2 秒一次」不是解药：① 出口策略层直接拒绝直连；② 正文与列表依赖 JS 调
保存 API；③ 站点自己已因自动化请求降级。**不刷保存 API** 这条不因降频放宽。

### 已交付：`site/lowfreq_fetch.py`

把用户认可的「2 秒一次」做成**可配置、有序、可断点续传**的取回器：

- `--delay 2.0`（默认，低于 1 秒直接拒绝）、`--base` 可切保存站 / luogu.com
- 队列只消费主表里 `是否题解=是 且 可逐字验证 != 是` 的条目，按题号升序；
  **不遍历 36⁸ 编号空间、不并发、不猜 ID、不登录**
- 结果写 `site/data/ingested/<lid>.json` + `取回日志.jsonl`，
  粗判「是否题解」，**不自动改主表**
- 命中「服务降级公告 / Request denied / 队列堵塞」或 HTTP 403/429/5xx →
  **立即停止本轮**，不重试轰炸
- 生成器 `_build_site.py` 会自动合并 ingested 正文到文章页，闭环完整

配套 `02_文章编号索引/编号池_待取回.md` 说明有序补录流程：
明确编号 → `ingest.py` 追加 → `lowfreq_fetch.py` 取回 → 人工判定 → 重生成站点。

## 5. 差点误判 / 自查

1. **以为保存站 403 是限流**：看到 403 第一反应是「降频就行」，但响应体写明
   `No policy rule matched the request` / `policy_default_denied`，是**策略网关默认拒绝**，
   不是 429。换 UA、换路径、2 秒间隔全都一样。
2. **以为「文章广场」能列编号**：保存站导航里有「文章广场」「统计数据」，
   逐个取回才发现全是 SPA 骨架，连归档总数都没有。静态取回拿不到动态数据。
3. **搜索摘要 ≠ 正文**：本轮 3 轮检索返回的 P1055 / P1980 / P2669 代码都是
   `displayable:false` 的摘要片段，且**无 8 位编号**，按纪律不拿来验证。
   本批 3 篇全部来自可逐字取回的 `article/<lid>` 正文。
4. **`88laurj5` 的 `a[i-1]` 越界读**：代码在 `if(i==0)` 之前就已经读了 `a[i-1]`，
   属 UB；但实测 i=0 的用例输出正确，按「题面内确定性 WA」不单独计缺陷，只登记。
