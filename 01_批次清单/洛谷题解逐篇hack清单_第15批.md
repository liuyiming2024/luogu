## 2. 四篇丙类，逐篇说明

### P1012 `ngy7hblx` · 拼数

```cpp
bool cmp(string a,string b){ return (a+b)>(b+a); }
sort(s+1,s+n+1,cmp);
```

题面 `1≤n≤20, 1≤aᵢ≤10⁹`，`string s[50]` 足够。两套**独立正确解**对照：

- 210 组 n≤7 走 `itertools.permutations` 全排列暴力，取拼接串字典序最大
  （所有拼接串等长，字典序最大即数值最大）
- 6 组（含 n=15/20、两个官方样例）走**插入法**：逐个把新串插到当前序列所有位置取最大，
  与 `sort+cmp` 是完全不同的构造路径

全部 0 不一致。题解文字里「321 和 37，字典序 351>32，32321>32114」是页面吞字符的乱码，
不是代码写错，按「代码只是辅助、不判文字笔误」处理。

### P1328 `a8f6uiq9` · 生活大爆炸版石头剪刀布

25 格 `score[a][b]` 手工打表，逐格与题面胜负表核对一致（1=小A胜 / -1=小B胜 / 0=平）。
`anum/bnum` 从 1 起、每轮 +1、越界回 1，周期模拟正确；`int a[m+1],b[k+1]` 是 VLA
（GNU 扩展，用 `-std=gnu++17` 编译），题面 `n,na,nb≤200` 内不越界。
402 组（2 个官方样例 + 400 组随机周期）0 不一致。VLA 属代码风格，按口径不计缺陷。

### P1424 `ju6tr560` · 小鱼的航程

`cnt+=1250*temp`（`temp=n/7`）处理整周，再对 `n%=7` 天从周 x 起逐天累加 `a[x]`，
`if(x>7)x-=7` 回绕。题面 `1≤x≤7, 1≤n≤10⁶`，最大里程 1.79×10⁸ < INT_MAX，
`int cnt` 不溢出。312 组含 `(1,10⁶)`、`(7,10⁶)`、`(3,999999)` 满规模，
与**逐天模拟全部 n 天**的独立解 0 不一致。

> 自查：搜索摘要把 `for(int i=1;i<=n;i++)` 吞成 `i7`、打表数组被拆散；
> 第一次逐字取回还把 `int temp=n/7;` 显示成全局初始化。**回原文二次确认**才拼对顺序：
> `scanf("%d%d",&x,&n)` → `int temp=n/7`（main 内局部）→ `n%=7` → `cnt+=1250*temp`。
> 顺序若反了，整周里程就用未读入的 n 算，结论完全不同。

### P1909 `v5aspqez` · 买铅笔

`ans=2147483647`，`ans=min(ans, b*((n+a-1)/a))`。题面「所有 7 个数 ≤10000」，
上界 `10000×10000=1e8`，`int` 不溢出；3 个官方样例（57 / 9998 / 9999）全对，
共 506 组 0 不一致。标题「为什么不能提交呢」与「复活币」是作者发表坎坷
（先把代码发到讨论区被撤销自由发言权），**不是代码缺陷**，按口径不拿来 hack。

## 4. 补记：P1008 `azdjstpm` 从「登记·不计数」升为丙（UB 登记）

上一轮它被挂起：沙盒 `www.luogu.com/article/azdjstpm` 两次都是
「标签加载失败 / Request aborted」，`luogu.com.cn` 返回内容安全审核拒绝，
保存站仍是 SPA 导航骨架；搜索摘要显示 `int st[9], bok[9]={0};` 配
`for (int i = 1; i <= 9; i++)` 使用 `bok[i]`，疑似 `bok[9]` 越界。

**Actions 出口把它取回来了**（run `45410907569`，HTTP 200，8836 字节 HTML，
`<pre>` 里完整代码块），逐字代码：

```cpp
int st[9], bok[9] = {0};
...
for (int i = 1; i <= 9; i++) {
    if (bok[i]) continue;
    bok[i] = true;  st[step] = i;  dfs(step+1);  bok[i] = false;
}
```

`bok[9]` 是**确定存在的越界写**（合法下标 0..8）。但按口径必须实测到后果，
不能凭直觉判（第 7 批 P1003、第 8 批 `g17kwzzm` 都是反例）。地址探针 + 五个优化档编译：

| 优化档 | `bok[9]` 与 `st[0]` 地址差 | 输出 4 组解 |
|---|---|---|
| -O0 | +100（`bok` 在 `st` 之后） | ✅ `192 384 576` / `219 438 657` / `273 546 819` / `327 654 981` |
| -O1 / -O2 / -O3 / -Os | −28（布局翻转，`bok[9]` 落在 `st` 之前的空隙） | ✅ 同上 |

五档全部 rc=0、输出 4 行正确解。结论：**UB 但题面内确定性输出正确** →
按「存在测试点使题解代码无法通过」的定义**不成立**，归**丙（UB 登记）**，
甲类反例不增加。这是「数组越界必须实测到具体规模」纪律的又一次胜利。

## 6. 全量爬取与校对架构（本批新增交付）

按「所有公开题面 / 公开题解 / 有用学术文章都汇集并校对」+「大脚本一直跑、
但每小时歇十分钟」+「保存站可先刷新，或直接爬洛谷」，新增：

| 文件 | 作用 |
|---|---|
| `tools/crawl_daemon.py` | 大脚本：有序枚举 → 取回 → L0/L1 校对 → 实时 push → 跑 50/歇 10 |
| `.github/workflows/crawl_tick.yml` | 每 6 小时轻量兜底（约 3 分钟/次，额度内） |
| `02_文章编号索引/全量爬取与校对说明.md` | 完整架构、节奏参数、三层校对、额度限制 |

要点：

- **有序枚举**：P 号顺序推进题面；题解走「主表待补队列 + 从正文 BFS 发现的新 8 位 ID」。
  **不遍历 36⁸ 编号空间**——这正是你早先定的「枚举是有序，不是高频」。
- **保存站刷新**：`--refresh-url` / `--refresh-cmd` 可插拔 hook，每个窗口开始调一次。
  保存站**没有公开刷新 API**（首页只有降级公告，各页全是 SPA 骨架），
  所以**不编造接口**；不配置就直爬 `www.luogu.com`。
- **节奏**：不是恒定 2 秒。间隔 2.0~3.5 秒抖动、每 20 次小憩 ~30 秒、
  跑 50 分钟歇 10 分钟、每日 2000 请求上限、被拒长退避 30 分钟。
- **实时写回**：每 10 篇或 10 分钟 `commit + pull --rebase + push`，
  state 断点续传；每窗口重生成离线站。
- **校对三层**：L0 编目判定 / L1 代码块与去重留证 / **L2 只进待对拍队列**。
  **全量自动判甲/乙/丙不可行**（每题需独立正确解），这一点如实写进文档，不越权。
- **Actions 额度**：私有仓库约 2000 分钟/月，50 分钟/小时常驻 ≈ 36000 分钟会烧光，
  所以 Actions 只做兜底；**真正长期跑在你自己的机器上** `crawl_daemon.py --forever`。
  沙盒只做 `--dry-run` 冒烟，不假装后台常驻。

   改为并行调用 / 前台执行后正常完成——也是「长期跑不能放沙盒」的实测依据。
3. `ju6tr560` 的 `int temp` 声明位置（见 §2），回原文二次确认。

5. `a8f6uiq9` 的 VLA、`azdjstpm` 的 `bok[9]` 越界：都属 UB/风格，
   **题面内确定性输出正确** → 不计缺陷，只登记。
